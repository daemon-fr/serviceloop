**Scope:** local-first presentation and search projection only; no Room schema or lifecycle/recurrence changes.

## Template tools

The expanded template-item strip remains the ordered `Remove | Move up | Move down | Done` row with accessible 48dp cells. Each visible symbol is now a layered Phosphor composition: a `circle-fill` base plus a semantic foreground `x`, `arrow-up`, `arrow-down`, or `check` glyph. The cell itself has no circular background. Remove uses destructive red/white, Move uses pale selection teal/dark action teal, and Done uses action teal/white. Disabled movement uses the existing disabled palette and disabled semantics.

The additional Phosphor aliases are generated from `tools/phosphor/serviceloop-icons.json`; vector drawables and the Kotlin icon API are generated by the repository tool rather than hand-authored.

## Register and templates

Register remains the third root destination and now has exactly four content tabs: Customers, Sites, Equipment, and Templates. The one-time-customer filter is rendered only for the first three tabs and retains the existing `UiFilterPreferences` memory. Templates loads on demand when its tab becomes active and exposes the shared `InspectionTemplateLibraryContent`: active masters first, disabled masters after, current revision/item count, status badge, detail navigation, and `Create inspection template`.

The legacy `template/list` route remains as the technical/deep-link/import surface for incoming `.slinsp` packages. It uses the same library content and exchange controls as Register. Settings no longer exposes a duplicate ordinary template-library entry; the incoming package role/import path remains unchanged.

## Grouped Search

Search groups non-empty results in this fixed order:

`Customers`, `Sites`, `Equipment`, `Templates`, `Service plans`, `Visits`, `Follow-ups`, `Final records`.

Each quiet section strip shows the current count, a caret, and expanded/collapsed semantics. Stable keys (`CUSTOMER`, `SITE`, `EQUIPMENT`, `TEMPLATE`, `PLAN`, `VISIT`, `FOLLOW_UP`, `FINAL_RECORD`) are persisted in `SearchUiPreferences`; a category defaults to expanded and remembers later changes across Search entries. Raw type/status metadata is removed from neutral rows. Context now comes from the typed DAO projection, and templates search one non-deleted logical master using its current revision, item count, and `template/{id}` route.

Visit, service-plan, and follow-up rows receive state only from the global `OperationalDashboardProjection` (`VISIT`, `SERVICE`, and `FOLLOW_UP` respectively). Customer-scoped projections are ignored, and Search does not sample a new clock or duplicate urgency classification. Neutral entities remain neutral. Accessibility descriptions include the useful operational label when a state is available even though the raw state is not shown as row noise.

## Recent searches and privacy boundary

`SearchUiPreferences` stores presentation-only state in application-private SharedPreferences named `serviceloop_search_ui_preferences`. It is not Room data and is not included in backup, export, Dispatch, reports, or sync. Up to ten meaningful queries are retained newest-first. Queries are trimmed, repeated whitespace is collapsed, and case-insensitive duplicates are promoted rather than duplicated. Blank/partial typing is not recorded; IME Search, result selection, and selecting an existing suggestion record/promote the query.

When a focused blank field has history, a bounded inline recent-search panel appears under the field. Selecting a row fills and executes the query; `Clear recent searches` removes the convenience state without touching business records. The field uses the Search IME action.
