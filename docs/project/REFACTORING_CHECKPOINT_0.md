## C1 — Dispatch finalization atomicity

**Confirmed and corrected** in `ServiceLoopRepository.finalizeVisit()`. Repository initialization normally inserts the primary Technician identity, but a later missing row is possible and the finalization operation must remain atomic. The old transaction inserted `final_records` and `final_record_revisions`, then returned `Blocked` normally when the Dispatch identity was missing; Room committed that normal return. A retry could then take the existing-record idempotent success path. The identity is now resolved inside the transaction before the first finalization write. Other post-write failures in this path throw and roll back; no remaining normal blocked return follows the first write.

`DispatchPackageTest.missingIdentityBlocksDispatchFinalizationWithoutPersistingPartialHistory` uses an isolated real Room database and removes only its test-owned identity after repository construction. Against the old production code it failed because persisted history changed after `Blocked` (captured in `app/build/reports/refactoring-checkpoint-0/c1-prefixed.log` locally). Against the correction it passes twice while identity is absent, checks the Visit, work, Dispatch bindings, and final history tables remain unchanged, restores the test identity, finalizes successfully, and verifies idempotent retry. `DispatchPackageInstrumentedTest.missingIdentityCannotPartiallyFinalizeDispatchVisit` repeats the failure/retry/success path on the canonical AVD with an in-memory Room database. Existing local and Dispatch success, participation-completion, and recurrence tests remain in the unit and focused connected coverage. This does not establish an incident in a real dataset; remediation of any pre-existing partial record would need a separate evidence-led decision, not automatic deletion.
